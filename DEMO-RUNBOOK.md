# Eight minute presentation runbook

Keep prepared speaking to 3–4 minutes and reserve 4–5 minutes for the actual website. Rehearse with spoken replies and transitions included.

Beforehand: run the final build in Chrome; sign in; apply the single hold-release migration; choose a real available screening and seats. Test the microphone and speakers. Start with Browser speech unless server transcription has passed your own live checks. Capture real screenshots for the PPT and keep a real screen recording as backup.

1. Show light/dark briefly and return to the preferred mode. Choose location view and search for a valid city. Do not spend the demo cycling every setting.
2. Open the guide. Say `Hi`. Ask for an action or comedy recommendation after the catalogue has loaded. Describe this as catalogue recommendations, not online web search.
3. Give an unsupported location (for example Atlantis) before setting a valid location, or an unsupported answer at the appropriate step. Show the explanation and recovery.
4. Select a real movie/date/time. Point out the movie context and the seven booking steps: Location, Movie, Date, Time, Tickets, Seats, Review.
5. Dictate `two adults and one student`. Let the spoken reply finish. Check three tickets. Choose three actually available seats and check quantities remain unchanged.
6. For a second recovery: demonstrate editing a recognised draft before Send, or at Review say `confirm looking` and show spoken clarification, then use the exact confirmation when ready. If dictation is accurate, describe draft editing as a controlled correction example.
7. Review, edit tickets/seats, choose available seats again and review. Verify the earlier hold was released. If migration is not available, avoid presenting the five-minute hold limit as fixed.
8. Choose payment, confirm explicitly and show one ticket per seat. Demonstrate the print-layout choice without spending time on printer setup. No money is processed and the ticket is not valid for real admission.

If recognition fails, retry once and continue by typing. If the network fails, explain the error and use a genuine rehearsal recording. Do not show generated concept images as a live working screen.

Usability testing is still required with at least three users. Add only actual tasks, observations, difficulties and improvements to the empty slide.
